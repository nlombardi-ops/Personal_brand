## Slice 3 of 3 — LOOP-03

**Vertical-slice framing.** After Task 1 Nicola can log the first quote for the garage-door motor
on that obra loop and see it there. After Task 2 he can line all three up side by side with the
cheapest flagged and the difference spelled out. After Task 3 he can correct a typo in a figure
or archive a quote that is no longer valid. No task is "add the entity" or "build the routes".

<assumption_delta_decision>
**Signal:** `pluralization` — LOOP-03 says "record **multiple** Presupuestos", and Slice 2's
`Document` is many-to-many with `OpenLoop`.

**Decision: `no-change`.**

`Presupuesto` and `Document` are *new* entities that are born plural. There is no prior singular
assumption being generalised — Phase 1's `OpenLoop` never had a single quote, a single price or a
single attachment field, so nothing is being widened. CONTEXT D-02 and D-10/D-16 already fix both
shapes as collections keyed to a loop.

The one alternative considered and rejected: promoting quotes and attachments to first-class
concepts ON `OpenLoop` (e.g. an array field for each). D-02 explicitly puts the document link on
`Document`, and nesting presupuestos on the loop would put a growing collection inside the record
that Phase 3's LPH engine is about to extend — the opposite of the PLAT-03 separation Phase 1
paid for. Keeping both as sibling stores keyed by `loop_id` / `linked_loop_ids` leaves `OpenLoop`
the same size it is today.

This is recorded, not enforced; it blocks nothing.
</assumption_delta_decision>

**`lib/community/presupuesto-defaults.ts`**:

`DEFAULT_IVA_PCT = 21` with a comment naming it the ordinary Spanish rate and noting that the
reduced rate for some reformas is entered by editing the field.

`computeTotalCents(baseCents: number, ivaPct: number): number` — one `Math.round` over
`baseCents * (1 + ivaPct / 100)`. Integer cents plus a single rounding step is what keeps the
deltas in the comparison exact; euro floats drift across the multiply and the subtract.

`parseEurosToCents(raw: string): number | null` — strip whitespace and any euro sign; when the
string contains both a dot and a comma treat the LAST of the two as the decimal separator and
remove the other as a thousands separator; otherwise treat a lone comma as the decimal separator;
require the result to match an optional integer part plus at most two decimals; return the value
in cents as an integer, or null for anything else. Negative values return null.

`formatEuros(cents: number): string` — `(cents / 100)` rendered with the Spanish locale and
exactly two fraction digits. Formatting happens at render only; nothing downstream of this
function is arithmetic.

`PATCHABLE_PRESUPUESTO_KEYS = Object.freeze(["provider", "base_imponible_cents", "iva_pct",
"scope", "received_at", "valid_until", "document_id", "status"] as const)`, with the
`loop-defaults.ts` lines 126-133 style comment recording that `id`, `loop_id`, `total_cents`,
`created_at` and `updated_at` are server-owned and therefore structurally unreachable from a patch
body. `total_cents` being absent is the mass-assignment mitigation, not an oversight.

`validatePresupuestoInput(body, opts: { create: boolean }): string | null` — Spanish messages,
`isPlainObject` guard first, caps: `provider` non-empty and at most 160 characters, `scope` at
most 2000 characters, `base_imponible_cents` an integer strictly greater than 0 and at most
100000000, `iva_pct` a number between 0 and 100 inclusive, `received_at` and `valid_until` null or
matching the date regex reused from `loop-defaults.ts` line 53, `document_id` null or a non-empty
string. On create additionally require `loop_id` and `provider`.

`applyPresupuestoPatch(existing, patch)` — copy the existing record, loop the frozen keys, guard
each with an own-property check, switch per key, never merge the body wholesale; then
unconditionally recompute `next.total_cents = computeTotalCents(next.base_imponible_cents,
next.iva_pct)` from the merged record. Unconditional is deliberate: it makes a patch that touches
neither figure a provable no-op on the total, and it means a client-sent total can never survive.
Refresh `updated_at` last.

`applyPresupuestoCreateDefaults(body)` — pick fields BY NAME, default `iva_pct` to
`DEFAULT_IVA_PCT`, default `scope` to the empty string, `status` to `"active"`, and compute
`total_cents`.
