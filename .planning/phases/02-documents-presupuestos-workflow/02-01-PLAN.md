<decision id="A1-client-upload">
## Decision: client uploads, not a server multipart route

`app/api/cv/versions/route.ts` — the natural copy source — stores a **server-generated** PDF
buffer, so it never crosses Vercel's request-body ceiling. A browser upload does. That ceiling
is **4.5 MB**, it is infrastructure-level, and it cannot be raised from code (RESEARCH §Summary,
verified against both the bundled `@vercel/blob/README.md` and `vercel.com/docs/functions/limitations`).
D-08 asks for ~15 MB and a real acta scan runs ~12 MB.

**Chosen:** browser → Vercel Blob direct via `@vercel/blob/client` `upload()`, with
`app/api/community/blob-upload/route.ts` acting as a `handleUpload` token broker. The file
bytes never enter a Route Handler.

**Tradeoffs accepted, in the open:**
- One extra route whose auth lives inside a callback rather than on line 1 — a deliberate,
  documented exception to the Phase 1 `requireAuth`-first rule (RESEARCH Pitfall 2).
- One file per request; multi-file (D-03) is a client-side loop, which is also what gives
  clean per-file failure isolation.
- Uploading while running `npm run dev` needs a Development-scoped `BLOB_READ_WRITE_TOKEN`
  (`user_setup`). Everything else — the metadata stores, the seeds, the list, the edits —
  works offline.

**If Nicola vetoes this** before execution: collapse `blob-upload/route.ts` into a single
`POST /api/community/documents` that reads a multipart body and calls `put()` server-side,
drop the client cap to ~4 MB, and accept that a full acta scan fails with a 413. Everything
downstream of `Document.blob_pathname` is unchanged either way.
</decision>

`FILE_TYPES` — a frozen map from canonical extension to `{ ext: readonly string[], mime:

`ALLOWED_MIME: string[]` derived from `FILE_TYPES` by flattening the non-empty `mime` arrays.

the lowercased `mimeType` to be a member of that entry's `mime` array (the empty string counts
only for the heic entry), return `null` if not; return the entry's canonical first extension,
its `kind`, and its `serve` string as `contentType`. Extension and media type must BOTH agree —
this one function is the gate the browser and the route each run.

reports for the object — a spoofed stored type must not be able to drive an inline render.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `blob-upload` token broker | An unauthenticated caller reaching this route could mint an upload token for our private store. |
| Vercel Blob webhook → `blob-upload` | A second, unauthenticated-but-signed caller hits the SAME route; the auth model must distinguish them. |
| browser → Vercel Blob (direct PUT) | File bytes never transit our code. Type and size limits are enforced only by what the minted token declares. |
| uploaded file bytes → rendered in the app origin | The proxy serves attacker-influenced bytes inline in `nl93.vercel.app`'s origin. |
| client JSON body → stored `Document` | Every field on the record is proposed by the browser; only some may be honoured. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Denial of Service | `blob-upload` token broker, upload path | high | mitigate | Three size gates: browser pre-check against `MAX_FILE_BYTES`, `maximumSizeInBytes` in the minted token (Vercel rejects before bytes land), and a `size <= MAX_FILE_BYTES` check on the metadata POST. The proxy streams and never buffers. |
| T-02-02 | Tampering / Elevation | `documents/[id]/file` inline response | high | mitigate | `Content-Type` from `serveContentType(doc)` — our own validated map, never the object's stored value — plus `X-Content-Type-Options: nosniff` and a default-src-none + sandbox CSP. No SVG and no office formats in `FILE_TYPES`, asserted by the allow-list test. |
| T-02-03 | Tampering | blob pathname construction | high | mitigate | Pathname is `community-documents/${crypto.randomUUID()}.${classified.ext}` — UUID plus an allow-list extension. `original_name` is stored as data and never used to build a path. The metadata POST re-validates the pathname shape before it is stored. |
| T-02-04 | Information Disclosure | `documents/[id]/file` | high | mitigate | The route takes a Document **id**, looks up the server-stored `blob_pathname`, and calls `get()` on it. It never accepts a path or URL from the caller, so it cannot be turned into a fetch-anything endpoint. |
| T-02-05 | Elevation of Privilege | `blob-upload` open token broker | high | mitigate | `requireAuth(request)` runs inside `onBeforeGenerateToken` before any token is minted, and throws on denial. Grep-asserted to be inside the callback (line order gate) so it cannot regress to a missing check. |
| T-02-06 | Spoofing | `blob-upload` webhook confusion | medium | mitigate | The SDK's `handleUpload` verifies Vercel's signed upload-completed callback itself. The browser path is cookie-authenticated in the callback. This is why `requireAuth` is deliberately NOT the route's first statement — documented in-code. |
| T-02-07 | Information Disclosure | direct private-blob URL access | high | mitigate | Every store and upload call uses the private access mode; the browser only ever receives `/api/community/documents/{id}/file`. Grep-asserted that no public access mode appears anywhere under `app/api/community/` or `lib/community/`. |
| T-02-08 | Tampering | mass assignment on `POST /documents` | high | mitigate | `applyDocumentCreateDefaults` picks fields by name and never spreads the body; `id`, `uploaded_at`, `file_kind` and `content_type` are all derived server-side, `file_kind` by re-running `classifyFile`. |
| T-02-09 | Tampering | prototype pollution via PATCH | high | mitigate | `applyDocumentPatch` iterates the frozen `PATCHABLE_DOCUMENT_KEYS` and reads each as an own property of the body — polluting keys are never read. Asserted by a test that checks the plain-object prototype afterwards. |
| T-02-10 | Access Control | archived document still downloadable | medium | mitigate | The proxy returns 404 when `doc.status === "archived"` (D-06), not merely hidden from the list. Grep-asserted and behaviour-asserted. |
| T-02-11 | Information Disclosure | error logging | medium | mitigate | No route logs the request body, filenames or titles — they can quote neighbour names (ASVS V7). Catch blocks build `err instanceof Error ? err.message : String(err)` only, mirroring the Phase 1 comment. |
| T-02-12 | Tampering (stored XSS) | `DocumentRow` rendering `title` / `original_name` | high | mitigate | Free text renders as React text children only; the raw-HTML injection prop is grep-asserted absent across `app/components/community/`. |
| T-02-13 | Denial of Service | orphaned blobs from failed metadata POSTs | low | accept | An upload that succeeds while its metadata POST fails leaves a blob with no record. No deletion or GC path exists in v1 (D-06). Storage cost for a single-user tool is negligible; recorded as a backstop truth for UAT. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new packages. `@vercel/blob`, `date-fns`, `lucide-react`, `framer-motion` are all pre-existing with an `OK` verdict in RESEARCH §"Package Legitimacy Audit" — no `[ASSUMED]` / `[SUS]` / `[SLOP]` entries, so no legitimacy checkpoint applies. Do not add an image-conversion or drag-and-drop library. |
